You are the expert on `packages/fledge_net`.

## Safety rules — do not violate

1. **Do not weaken encryption**. AES-256-GCM (`EncryptedTransport`) with the AAD-bound 6-byte plaintext header is the contract. Do not add cleartext fallbacks or downgrade paths. Do not "temporarily disable" auth for debugging.
2. **Pre-shared key distribution is the app's problem, not the plugin's.** Do not add a network-based key exchange without a formal design review.
3. **AAD is the 6-byte plaintext header** (`EncryptedTransport.plaintextHeaderBytes`: magic + version + type) — any change to the packet header layout in `protocol/packet.dart` requires re-verifying AAD binding. Getting this wrong silently breaks integrity.
4. **Authority transfer is a one-way trust boundary**. A client claiming authority it wasn't granted must be rejected. Preserve every existing authority check.
5. **State reconciliation** (server correcting client prediction) must be deterministic. Non-deterministic reconciliation causes rubberbanding; test with variable RTT.

## Domain knowledge

- Modes: `NetworkMode.offline` (default), `host`, `client`, set on the `NetworkConfig` resource. Host and client logic live in `connection/host.dart` and `connection/client.dart`; grep for `NetworkMode` and `config.mode` before making mode-dependent changes.
- Tick rate vs sync rate are separate (`NetworkConfig.tickRate` 60 Hz vs `syncRate` 20 Hz) — simulation ticks faster than state broadcasts. Do not conflate them. Prediction/reconciliation belong on `Schedules.fixedUpdate` (same `FixedTimestep` rate on host and client); running them in `Schedules.update` desyncs.
- Interest management filters what the host sends to each client by radius. Adding new interest criteria is fine; removing existing ones is a bandwidth regression.
- Congestion control is AIMD — additive increase, multiplicative decrease. If you touch the pacing, benchmark with lossy links. (`CongestionController` exists per peer but is **not yet wired** into the send path.)
- Protocol version is **3**. Header `timestamp` is the *sender's* `NetClock` value (monotonic `Stopwatch` ms, unsigned 32-bit, wraps). Never compare timestamps across machines; RTT comes from ping payload (uint32 sender clock) echoed unchanged in the pong, computed with `NetClock.elapsed32` (wrap-safe). Host pings each peer from `update()` every `pingInterval`; client pings from `update()`. `Peer.updateRtt` / client `_updateRtt` drop samples < 0 or > 60 s.
- Strings on the wire are UTF-8 with a uint16 byte-length prefix (`writeString` / `readString`); `writeBytes` also uses a uint16 prefix.
- Max datagram is `Packet.maxDatagramBytes` (1200); `Packet.maxPayloadBytes` (1152) reserves header + 28 bytes of encryption overhead even when unencrypted. Host/client send APIs throw `ArgumentError` above it (no fragmentation yet; the replication layer chunks snapshots and batches reliable messages itself, but one entity's state must fit in ~1.1 KB).
- Connect handshake: client re-sends the same connect bytes every `connectRetryInterval` (own `Timer`, independent of `update()`) until accepted/rejected/timeout; host ignores connects from addresses in `_pendingConnects` (async authenticator in flight) and re-sends `connectAccepted` to an existing peer that retries. Client ignores duplicate accept/reject once out of `connecting`. Connect retries and `connect()`'s overall timeout run on real timers (not `NetClock`).
- Disconnect notices are sent redundantly: `NetworkClient.disconnect()`, `NetworkHost.disconnectPeer()` and `stop()` send `disconnectRedundancy` (default 3) identical `disconnect` datagrams spaced by `disconnectRedundancyInterval` (default 5 ms), bounded wait. The host removes the peer after the first round; duplicates hit the unknown-peer / already-disconnected paths and are ignored. Same wire packet, so older v3 peers interoperate.
- Host peer timing is on `NetClock`: `Peer` takes `clock:` (host passes its own), `lastReceiveMs`/`lastSendMs` drive `timeSinceLastReceive` and reliable retransmits. `Peer.lastReceiveTime`/`lastSendTime` remain (informational `DateTime`; assigning them shifts the ms values, so back-dating still forces a timeout).
- `Transport` delivery contract: each datagram exactly once — to `onReceive` listeners if any, else into a bounded buffer drained by `receive()`. `UdpTransport` drains all datagrams per read event and queues would-block sends (Windows returns 0 from `RawDatagramSocket.send` under bursts).
- Test multiplayer with `LoopbackNetwork` / `LoopbackTransport` (`lib/src/transport/loopback_transport.dart`): latency, jitter, loss, duplication, `filter`, seeded `Random`; manual mode with `ManualNetClock` + `advance()` makes RTT/timing exact (incl. host peer timeouts). Prefer it over hand-rolled mock transports.
- `package:fledge_net/testing.dart` (test-only, not exported from `fledge_net.dart`): `RawInputStream`, `encodeRawInputPacket`, `encodeWithCodec`, and the `NetworkSessionTesting` extension (`sendRawInput`, `sendRawInputPacket`, `sendRawRpc` via the `@internal` `NetworkSession.queueRpcForNetId`) for forging another peer's inputs/RPCs in authority tests. It wraps `wire.dart` encoders, so keep it in sync with wire changes.
- Inside an extension on `ReplicationRegistry`, call `this.component<T>(...)`: a bare `component` resolves to `fledge_ecs`'s top-level annotation constant.
- `NetworkClient.connect` accepts hostnames (resolved via `InternetAddress.lookup`, IPv4 preferred, or injected `hostResolver`). Transport is IPv4-only.
- **Replication layer** (`lib/src/replication/`): `NetworkSession` resource (`host()`/`join()`/`close()`) wires every `NetworkConfig` field: `serverPassword` (constant-time compare, client default credentials) + `authenticator` (both must accept), `enableEncryption` + `encryptionKey` (wraps `EncryptedTransport`; missing key throws, no fallback), `interestRadius`, `tickRate` (must equal `FixedTimestep`; checked at start and in the handshake), `syncRate`, `interpolationDelay`, `maxPeers`, `connectionTimeout`, `disconnectPolicy`, `inputLeadBufferTicks`, `maxInputRepeatTicks`, `inputRedundancy`. Stream callbacks only append to inboxes; the 7 plugin systems (always registered, no-ops offline) drain them: `NetPumpSystem` (first, `FirstSets.platform`), `NetReceiveSystem` + `NetInterpolationSystem` (first, after all phases), `NetTickSystem` (fixedFirst), `NetInputSystem` + `NetPredictSystem` (fixedPreUpdate, after `NetSets.localInput`), `NetSendSystem` (fixedLast).
- Authority on the host: inputs (`NetInputSystem` / `_onInput`) and targeted RPCs are accepted only if `NetworkIdentity.ownerId == peerId`; otherwise dropped, counted in `NetworkSession.stats`, and reported as `NetRejected` (ids + fixed reason, never payload). Clients may only send `rpc` reliable messages; spawn/despawn/parent/owner come from the host only. Keep these checks.
- Reliable replication traffic uses `ReliableChannel` (cumulative acks, ordered, deduped) over `PacketType.replication` (0x14, *unreliable* at Peer level); tick sync uses `PacketType.tickSync` (0x15). Payload formats are in `lib/src/replication/wire.dart`; changing them is a protocol change.
- Snapshots are full-state per relevant entity, chunked to `Packet.maxPayloadBytes`, every `syncInterval` ticks; delta-vs-acked-baseline is a future optimisation.
- Client tick: `ClientTickSync` leads the host by RTT/2 + buffer, corrected by FixedTimestep accumulator dilation; hard reset > 10 ticks clears prediction history. Prediction replays only the registered pure `step`.
- Test replication with `test/support/replication_harness.dart` (`NetTestbed`: host + N clients, manual clock, one fixed step per frame). The composed ordering check with real Flutter plugins lives in `integration/all_plugins` (fledge_net stays pure Dart; transforms are app-supplied codecs + `positionOf`).

## Rules for changes

- Protocol wire-format changes are breaking. Bump `PacketHeader.version` in `lib/src/protocol/packet.dart` (and its version-history doc comment) and keep the `peekVersion` paths: client fails with "Protocol version mismatch: local vX, server vY"; host rejects mismatched `connect`s with "Protocol version mismatch: host vX, client vY" (only replies to `connect`, never to other traffic); both emit `ProtocolMismatchEvent`.
- Public docs for this package live at `docs/assets/docs/plugins/net.md` (routed in `docs/lib/app/router.dart`); keep in sync when adding features.
- This package is pure Dart (no Flutter dependency; only `fledge_ecs`, `meta`, `pointycastle`), so tests run under `dart test` via `test:dart`. Keep it that way — adding `flutter` would move it to `test:flutter` and require updating the ignore list.
- **Never** log secrets (keys, tokens, session material).
